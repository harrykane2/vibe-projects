# 1\. Известные факты о продукте и аудитории

## 1.1. Информация о продукте

- Название: «Рядом».
- Назначение: помощь занятым родителям в выборе кружков и секций для детей.
- Основная задача: помочь родителям заранее оценить, насколько выбранное занятие подходит их семье.
- Ключевые критерии выбора:
    - Расположение и удобство дороги после работы.
    - Расписание занятий.
    - Стоимость занятий.
    - Соответствие предложения потребностям семьи.
- Особенность поведения аудитории: поиск подходящих занятий обычно начинается в родительских чатах.

## 1.2. Характеристика целевой аудитории

| **Критерий** | **Характеристика** |
| --- | --- |
| Возраст родителей | 28–42 года |
| Место проживания | Города с населением от 500 тысяч человек |
| Возраст детей | 4–12 лет |
| Основная потребность | Найти подходящие кружки и секции для ребёнка |
| Основные критерии выбора | Расположение, расписание, стоимость |

## 1.3. Результаты исследования аудитории

Команда провела 24 коротких интервью с родителями.

| **Выявленная проблема** | **Результат** |
| --- | --- |
| Дорога после работы — главное препятствие при выборе кружка | 15 из 24 |
| Сравнение предложений минимум в четырёх источниках | 11 из 24 |
| Прекращение поиска, если стоимость сообщают только по телефону | 9 из 24 |

**Основные выводы из интервью:**

- Удобство расположения и возможность добраться до занятия после работы имеют большое значение для опрошенных родителей.
- Поиск информации о кружках требует обращения к нескольким источникам.
- Отсутствие открытой информации о стоимости может стать причиной прекращения поиска.

**_Примечание:_** _один участник мог упоминать несколько проблем. Результаты относятся только к 24 опрошенным родителям и не характеризуют всю целевую аудиторию._

# 2\. Ограничения первой версии сервиса

## 2.1. Ресурсы и сроки

- Команда состоит из двух человек: основателя и дизайнера.
- Сайт и готовая разработка отсутствуют.
- На первый этап запуска отведён один месяц.

## 2.2. Что входит в первую версию (MVP)

- Запуск лендинга.
- Организация ручного подбора кружков и секций.
- Предоставление родителям нескольких подходящих вариантов занятий.

## 2.3. Что не входит в первую версию

| **Не входит в MVP** | **Ограничение** |
| --- | --- |
| Мобильное приложение | Не разрабатывается |
| Полный каталог секций города | Не создаётся |
| Автоматический поиск | Подбор осуществляется вручную |
| Личный кабинет | Не предусмотрен |
| Онлайн-оплата | Не предусмотрена |

# 3\. Вопросы, на которые пока нет ответов

Для дальнейшей работы над продуктом необходимо уточнить следующие моменты.

## 3.1. География и ассортимент

1.  В каких конкретно городах будет запущен сервис?
2.  Какие районы будут охвачены на первом этапе?
3.  Какие виды кружков и секций будут представлены?

## 3.2. Процесс подбора занятий

1.  Сколько вариантов занятий будет предлагаться одному родителю?
2.  По каким критериям будет осуществляться ручной подбор?
3.  Как команда будет определять удобство расположения и возможность добраться до занятия после работы?
4.  Где команда будет находить информацию о кружках и секциях?

## 3.3. Взаимодействие с пользователями

1.  Как родитель сможет оставить заявку на подбор через лендинг?
2.  Каким способом команда будет связываться с родителями?
3.  Как будет организована передача подобранных вариантов занятий?

## 3.4. Информация о предложениях

1.  Будет ли стоимость указана для каждого предложенного занятия?
2.  Как часто будет обновляться информация о стоимости, расписании и расположении?
3.  Каким образом команда будет проверять актуальность информации?

## 3.5. Организация работы и оценка результатов

1.  Сколько времени будет занимать обработка одной заявки?
2.  Сколько заявок команда сможет обработать за месяц?
3.  По каким показателям будет оцениваться успешность первой версии сервиса?
4.  Какой бюджет предусмотрен на запуск лендинга и организацию ручного подбора?

# 4\. План исследования: проверка спроса на ручной подбор кружков и секций

**Срок:** один месяц.

**Команда:** основатель и дизайнер.

## Шаг 1. Формулировка гипотезы спроса и критериев успеха

|     |     |
| --- | --- |
| **Вопрос** | Что именно проверяем и по каким измеримым признакам поймём, что спрос подтверждён или опровергнут. |
| **Достаточный результат** | Одна чётко сформулированная гипотеза (например: «занятые родители из выбранного города готовы оставить заявку на бесплатный ручной подбор кружка») и 2–3 метрики с целевыми значениями, по которым команда примет решение «продолжать / менять подход / остановиться». Формулировки согласованы основателем и дизайнером до запуска. |
| **Требует проверки источника** | Любые цифры о поведении аудитории сверх данных 24 интервью — выборка мала и не характеризует всю аудиторию, это прямо отмечено в исходных сведениях. Также гипотеза о готовности оставлять заявку — это предположение, а не факт: её проверяет сам план. |

## Шаг 2. Процедура выбора города

|     |     |
| --- | --- |
| **Вопрос** | По каким данным и какой процедуре команда выберет первый город и районы запуска. |
| **Достаточный результат** | Утверждённый список критериев (численность населения задана — от 500 тысяч; добавить стоит плотность предложения секций, доступность родительских чатов, конкуренцию), список из 3–5 городов-кандидатов и таблица с источниками данных по каждому критерию. На этом шаге город ещё не выбран — только собраны данные для решения. |
| **Требует проверки источника** | Сведения о городах из общих знаний — численность населения, наличие секций, активности родительских сообществ. Каждый факт брать из первоисточника (статистика населения, карты, городские каталоги, сами чаты), а не из памяти модели или пересказов. |

## Шаг 3. Сбор данных о предложениях и процедура выбора категорий

|     |     |
| --- | --- |
| **Вопрос** | Какие категории занятий включить в ручной подбор и где команда будет брать информацию о секциях — с учётом барьера «дорога после работы» и требования открытой стоимости. |
| **Достаточный результат** | Инструкция по сбору данных (какие поля фиксировать о каждой секции: адрес, время занятий, стоимость, доступность информации без звонка) и список из 2–3 категорий-кандидатов, отобранных по данным интервью, с планом мини-проверки интереса в родительских чатах выбранного города. Ответ на вопрос «какие категории включить» принимается по этим данным, а не по общим предположениям. |
| **Требует проверки источника** | Данные о конкретных секциях, их расписаниях и ценах — обязательно из первоисточников на момент исследования; они меняются часто. Утверждения о «популярных видах спорта и творчества» в конкретном городе — только по результатам опроса и каталогов. |

## Шаг 4. Лендинг и регламент ручного подбора

|     |     |
| --- | --- |
| **Вопрос** | Как устроить заявку на лендинге и процесс подбора, чтобы снять три барьера из интервью: неудобную дорогу, необходимость сравнивать несколько источников и скрытую стоимость. |
| **Достаточный результат** | Структура лендинга и форма заявки (что родитель указывает: район, дни, бюджет, возраст ребёнка), регламент подбора: сколько вариантов выдавать на одну заявку, по каким критериям фильтровать, где проверять актуальность информации, как передавать варианты родителю. Регламент протестирован на 2–3 пробных заявках от знакомых. |
| **Требует проверки источника** | «Лучшие практики» лендингов из общих знаний — это гипотезы до подтверждения своими цифрами. Требования к обработке персональных данных при сборе заявок — только по первоисточникам законодательства, не по пересказам. |

## Шаг 5. Запуск, распределение задач и оценка месяца

|     |     |
| --- | --- |
| **Вопрос** | Как за четыре недели привлечь первых пользователей из родительских чатов, выдержать поток заявок вручную и оценить результат по метрикам из шага 1. |
| **Достаточный результат** | План на четыре недели с ролями основателя и дизайнера; расчёт пропускной способности — время на обработку одной заявки умножается на доступные часы команды, это определит, сколько заявок реально обработать без потери качества; способ распространения в родительских чатах с учётом их правил публикации; дата подведения итогов по метрикам шага 1. |
| **Требует проверки источника** | Прогнозы числа заявок — модель не может их знать, их заменяет расчёт пропускной способности команды; правила публикаций в конкретных чатах — уточняются у администраторов; оценки затрат на лендинг — по реальным тарифам конструкторов на момент запуска. |
